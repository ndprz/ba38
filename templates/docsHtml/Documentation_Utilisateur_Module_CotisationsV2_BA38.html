Documentation Utilisateur — Module Cotisations V2 BA38

Objectif

Traiter le fichier PARSOL2L annuel des cotisations, générer automatiquement les factures PDF, les envoyer par email aux associations, suivre les paiements et relancer les impayés — le tout depuis un seul module, sans dépendance à Google Drive.

Ce module coexiste avec l’ancien flux “📂 Cotisations 2026” jusqu’à son retrait prévu fin 2026. Les deux systèmes utilisent des tables séparées : aucune donnée n’est partagée entre eux.

  1. Accéder au module

Menu → Trésorerie → section “Cotisations” → “📊 Cotisations V2 (traitement + envoi + relances)”.

  1. Traiter un fichier PARSOL2L

  • Choisir l’année concernée dans la liste déroulante.

  • Si une campagne existe déjà pour cette année, une fenêtre propose soit de voir les factures déjà générées, soit de retraiter un nouveau fichier (attention : retraiter écrase les factures existantes tant qu’aucun envoi réel n’a eu lieu ; c’est bloqué dès qu’au moins une facture a été réellement envoyée).

  • Sélectionner le fichier PARSOL2L annuel (.txt) et indiquer le numéro de facture de départ.

  • Cliquer sur “🔍 Analyser et générer” : les factures sont créées, numérotées dans l’ordre du compte comptable.

  • Règle de regroupement : si une association a un code de regroupement renseigné sur sa fiche (champ “vif_regroup_cotisation”), ses bénéficiaires sont cumulés sur l’association “maître”, qui reçoit une facture unique pour l’ensemble. Le barème appliqué (50 €, 80 € ou 110 € selon le nombre de bénéficiaires) reste identique à l’ancien flux.

  1. Écran Résultats

Affiche la liste des factures de la campagne : numéro de facture, association (avec mention du regroupement si applicable), code VIF, email, bénéficiaires, montant, statut Payé, PDF, statut d’envoi, statut Mailjet, renvoi Gmail.

  • “👁️ Voir” : ouvre le PDF de la facture (régénéré à la demande).

  • Bandeau “Mode TEST / Mode PROD” en haut de l’écran : commun à tout le module trésorerie ; en mode TEST, les envois ne partent que vers l’adresse de test (2 mails maximum).

  • “📧 Envoyer les mails” : choisir un modèle d’email puis envoyer — seules les factures pas encore envoyées sont concernées.

  • “🔄 Vérifier statut Mailjet” : met à jour le statut de délivrabilité (remis, ouvert, rejeté…) des mails déjà envoyés.

  • “🔁” (colonne Gmail) : renvoie la facture via Gmail en cas de rebond Mailjet — uniquement disponible si le dernier envoi était réel (pas en mode TEST).

  • “🔔 Relancer les impayés” : ouvre l’écran de relance (voir section suivante).

  • “📤 Retraiter un nouveau fichier” : recommence le traitement pour cette même année.

Les codes VIF du fichier qui ne correspondent à aucune association connue apparaissent en bas de l’écran dans une liste “Associations non trouvées en base” — ils sont automatiquement rattachés dès qu’une association avec ce code VIF existe ou est corrigée par la suite (voir Points d’attention).

  1. Marquer une facture payée

Le bouton “⬜ Marquer payé” / “✅ Payé” (colonne Payé) bascule l’état payé/impayé d’une facture en un clic, sans recharger la page. Une facture marquée payée n’est plus proposée dans les relances.

  1. Relancer les impayés

Depuis l’écran Résultats, “🔔 Relancer les impayés” affiche la liste des factures déjà envoyées et non encore payées.

  • Choisir le numéro de relance (1ère, 2ème ou 3ème) et l’expéditeur du mail, puis cliquer sur “🔎 Prévisualiser” pour voir la liste des associations concernées et le montant total.

  • Si une association n’a pas d’adresse email connue, un message d’avertissement orange l’indique dès cet écran, avant l’envoi.

  • Valider avec “🚨 CONFIRMER L’ENVOI” (une case à cocher supplémentaire est demandée en mode PROD, par sécurité). L’envoi se fait en arrière-plan.

  • La relance renvoie la même facture PDF que l’envoi initial (pas de mention “rappel” spécifique sur le document) — seul le texte de l’email diffère.

  • Comme sur l’écran Résultats, “🔄 Vérifier statut Mailjet” et le renvoi Gmail par ligne sont disponibles pour les relances déjà envoyées.

  1. Points d’attention

  • Le mode TEST / PROD est un réglage partagé avec l’ancien flux “Cotisations 2026” et le reste du module trésorerie — le vérifier avant tout envoi réel.

  • L’email utilisé pour une facture est celui de l’association au moment du traitement du fichier PARSOL2L. S’il a été ajouté ou corrigé depuis, l’application utilise automatiquement l’adresse actuelle de l’association pour les relances, et l’enregistre sur la facture dès qu’une relance réussit avec cette adresse.

  • Une association absente de la base au moment du traitement (facture “orpheline”) est automatiquement rattachée dès qu’elle est créée ou corrigée par la suite — un message de confirmation s’affiche à la prochaine ouverture de l’écran Résultats. Le montant est alors recalculé sur les seuls bénéficiaires de cette ligne (un éventuel regroupement ne peut pas être reconstitué automatiquement dans ce cas — à vérifier manuellement si besoin).

  • Le renvoi via Gmail n’est possible que pour une facture (ou relance) dont le dernier envoi était réel — un envoi effectué en mode TEST ne peut pas être “renvoyé pour de vrai” par ce bouton.
